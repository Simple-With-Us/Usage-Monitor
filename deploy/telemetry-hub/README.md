# Server Telemetry Hub

The custom Node hub runs with a durable named volume and defaults to host loopback at port 4318.  The container publishes no public port or domain.  This Linux host-network configuration works for same-host producers; Mac/cloud producers require a private authenticated ingress route before rerouting.  Never publish an unauthenticated receiver through a public Coolify proxy.

The deployment defaults to Sentry-only delivery and projects finite counters and bounded identifiers before journaling.  Prompt/response/tool content, arbitrary metadata, source names and raw attribute containers are excluded.  Usage Monitor's existing collectors continue their independent billing ingest.  This avoids activating the older hub's platform exclusion and minute-bucket cash dedupe policy.

The preferred bootstrap retains only a dedicated read-only `INFISICAL_TOKEN`, its `INFISICAL_PROJECT_ID` project address, and a verified `INFISICAL_API_URL` if the organization uses a custom endpoint.  The pinned CLI reads prod `/telemetry` on startup with imports, recursive lookup and expansion disabled.  No machine identity fallback is present.  Actual destination/source settings belong in that exact Infisical folder, including the verified agent-sessions project's `SENTRY_OTLP_ENDPOINT` and `SENTRY_PUBLIC_KEY`.  The endpoint ends in `/integration/otlp`; no bearer or key belongs in this repository or shell argv.  This Sentry-only deployment needs no Usage Monitor token.  Configure no Coolify domain, public port mapping or replica scaling; one writer owns the journal volume.

The initial rollout has an explicitly authorized snapshot fallback because the available administrative route cannot create the required dedicated service token.  Infisical prod `/telemetry` remains the source of truth, and the bootstrap limitation is tracked separately.  An authorized deployment helper refreshes a private configuration snapshot directly from that source for each deployment; the platform stores only its mounted file path, never the snapshot's secret values or a broad automation identity.

For that fallback, combine `compose.yml` with `compose.snapshot.yml` and provide `TELEMETRY_HUB_CONFIG_SNAPSHOT_PATH` through the private deployment configuration.  The runtime mounts it read-only at `/run/secrets/telemetry-hub.json` and explicitly sets `TELEMETRY_HUB_CONFIG_FILE` to select snapshot mode.  Its exact JSON schema has only three required nonempty string values: `SENTRY_OTLP_ENDPOINT`, `SENTRY_PUBLIC_KEY`, and `TELEMETRY_HUB_SOURCES_JSON` (the source array encoded as a JSON string).  The regular file must be owned by runtime UID 10001 with exact mode 0600; symlinks, permissive modes, unknown/missing fields, malformed values and files larger than one MiB are refused.  Mounted snapshot values override ambient destination/source variables, and broad Infisical identity variables are stripped before launching the hub.  Snapshot and service-token modes are mutually exclusive; a failed token bootstrap never silently falls back to a file.  Move to the scoped-token mode only after that owner-managed access exists and is verified.

Build from the repository root with `docker build -f deploy/telemetry-hub/Dockerfile .`.  Use `deploy/telemetry-hub/compose.yml` for the service definition after verifying loopback port 4318 is free and the configured project is agent-sessions.  Container health proves the local receiver is listening; it does not prove downstream receipt.  Verify a bounded allowlisted test span reaches the intended Sentry project and survives a container restart before changing producer exporters.

For private remote ingress, set `TELEMETRY_HUB_BIND_HOST` to the server's verified Tailscale address and supply `TELEMETRY_HUB_SOURCES_JSON` through the approved secret configuration route.  Its array contains `{id, platform, token}` for each approved source; tokens have at least 32 non-whitespace characters, and identifiers use lowercase letters, digits, dots, underscores and hyphens.  Non-loopback startup refuses an empty source list.  Each bearer maps to server-owned platform/source identity, overrides producer claims, namespaces event IDs and stamps the source on each journal event.  Source-token rotation may retain two tokens for the same identity without changing receipt identities.  Do not expand an Infisical token's folder scope or create a machine identity to satisfy this example.

The companion collector bridge is disabled until `COLLECTOR_SENTRY_ENABLED=1` is set.  For server-hub delivery provide `COLLECTOR_TELEMETRY_HUB_ENDPOINT` and the scoped `COLLECTOR_TELEMETRY_HUB_TOKEN`; remote collectors need no Sentry key.  A shared per-host collector environment instead supplies `COLLECTOR_TELEMETRY_HUB_TOKENS_JSON`, mapping the exact producer IDs `claude-code`, `openai-codex`, `opencode` and `minimax-code` to their separate source bearers.  Unlisted producers stay disabled, and each host receives only its own token map.  Plain HTTP is allowed only for loopback or a Tailscale address; other destinations require HTTPS.  Alternatively a direct Sentry bridge uses the exact-project endpoint/key above.  Optional `COLLECTOR_SENTRY_STATE_DIR` relocates its outbox, with separate durable receipts for every destination, producer and machine.  Known Claude/opencode calls become spans; Codex and MiniMax rows without an authoritative provider-call identity remain token observations.  No telemetry is dropped by approximate timing; existing Usage Monitor event IDs and quantities are unchanged.  Claude additionally carries opaque `call.id` correlation metadata, so deploy its server replay support before upgrading collectors.

Failed Sentry sends retain the SQLite outbox; failed outbox writes allow UM delivery but retain the source checkpoint for idempotent replay.  ACK state is independent from UM, and normal empty-source passes of the four primary collectors still drain their existing outbox.  Process birth/boot fingerprints recover dead or reused-PID ownership.  Batches are bounded to 100 records per request with a five-second invocation delivery budget; remaining records stay pending for the next invocation.  No retry expiry is imposed.  Crash recovery is at-least-once, including the unavoidable acceptance-before-local-ACK crash window.

An invalid or permanently rejected row is isolated and retained as `quarantined`; healthy rows continue.  After inspecting and correcting the cause, `node scripts/retry-collector-sentry-outbox.mjs --outbox-dir <producer-destination-directory> --event-id <exact-quarantined-id>` requeues that one stored row without sending network traffic.  Quarantine counts produce a warning, and quarantined payloads are never eligible for receipt pruning.

Receipt cleanup is an explicit bounded operation: `node scripts/prune-collector-sentry-outbox.mjs --outbox-dir <producer-destination-directory> --checkpoint-file <verified-producer-checkpoint> --retention-days 180`.  It removes at most 10,000 acknowledged receipts whose source timestamp is outside the checkpoint's 180-day lookback plus one-day overlap and whose ACK is also older than 180 days.  Pending/in-flight telemetry is never eligible, and the recorded prune boundary remains in metadata.  Use a larger retention value if a collector has a longer configured lookback.  An explicit historical backfill older than the prune boundary may resend Sentry observations; it does not change UM cash dedupe.  SQLite reuses freed pages; this operation does not rewrite or truncate the live database.

Run `node --test scripts/collector-sentry-bridge.node-test.mjs scripts/telemetry-hub-auth.node-test.mjs scripts/telemetry-hub-bootstrap.node-test.mjs`, `npx vitest run scripts/telemetry-hub/__tests__` and `npm run test:session-token-collectors` before rollout.  No command in this document provisions credentials or changes a host automatically.
