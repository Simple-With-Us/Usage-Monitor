## Finite Lifecycle Model Prepared Offline

`scripts/telemetry-hub/finite-pinned-lifecycle.py` adds a separate finite wrapper around the offline pinned lifecycle.  Its exact plan keys are `schema`, `lifecycle`, `snapshot`, `reservation_sha256`, `rollback_plan_sha256` and `limits`.  Schema is `telemetry-hub-finite-lifecycle/v1`.  `lifecycle` retains the existing exact target/image/daemon/config/volume digest fields.  `snapshot` contains old/new whole-snapshot and map digests plus complete sorted new membership.  `limits` requires bounded `total_seconds`, `phase_seconds` and `health_checks`; no default expands a missing field.

The model's Engine allowlist fixes every method/path/status/body digest, including stop `t=15`, no-force/no-volume removal, exact same-name create, and one start bound only to the confirmed fresh full ID.  It permits no volume/image/network mutation or arbitrary exec/archive read.  Route counts and health sampling give a maximum of `24 + 2 * health_checks` logical calls.  These are model-level calls; a later live mutation transport must independently count its daemon probes and wire requests.  Each mutation requires the preceding proof boundary, has a private intent and bounded private response receipt, and is attempted once.  Completion and every failure seal the instance against further calls or resumption.

Four named one-shot proof phases replace free-form continuation callbacks:

- `preflight-recovery`: exact snapshot backup readback, complete old inspect and pinned payload readback, UID/GID/mode/file identity, existing member/Sentry-field preservation, current reservation digest and exact reconstruction-plan metadata before stop.
- `stopped-transition`: one reviewed old-to-new snapshot transition, preserved custody with a changed inode on the same device, exact before/after stopped journal equality, no pending compaction and unchanged reservation before old-container removal.
- `prestart`: the actual stopped replacement's snapshot bytes, exact new file identity and unchanged same-volume journal before start.
- `poststart`: actual mounted snapshot/custody plus same-volume journal continuity, nondecreasing end/offset and unchanged dead-letter size before success.

Proof operations receive cooperative deadlines, and the wrapper checks phase and whole-run deadlines before and after every synchronous proof or private-receipt invocation.  An overdue operation remains owned until it returns; there is no background timeout, cancellation claim or early lease release.  After return, expiry is terminal and no later Engine action occurs.  This bounds further progress but cannot forcibly preempt a blocked kernel operation or arbitrary injected Python callback.  The new host adapter uses nonblocking regular-file opens, bounded reads and deadline checks around its fixed synchronous operations; it does not claim to cancel a blocked kernel operation.

The receipt sink must acknowledge exclusive/fsynced/readback durability with the exact canonical data hash and Boolean `durable_readback=true`; a corrupt/missing acknowledgment is terminal.  The original model tests use memory receipts, while the host-adapter tests now exercise actual exclusive writes, file/directory fsync and bounded exact readback on synthetic temporary files.  A live stopped-container snapshot readback route, finite mutation transport and reviewed production wiring remain missing.  The real supplied backend continues to refuse every mutation, even if the model allowlist and proofs accept it.

## Host Proof And Durable Receipt Candidate

`scripts/telemetry-hub/host-proof-adapter.py` implements the scoped filesystem phases and durable receipt contract.  Its default CLI emits an offline status with zero filesystem/Engine operations; `--execute` refuses before opening any path.  It contains no credential client, Docker command, Engine call, runtime restart or live mounted-container reader.  The finite CLI and real transport mutation refusals remain unchanged.

The exact host scope fields are `snapshot_path`, `new_snapshot_path`, `reservation_path`, `journal_path`, `receipt_directory`, `owner_session`, `snapshot_owner`, `journal_owner`, `input_owner` and `pins`.  Every path is absolute and normalized; owners are exact UID/GID pairs.  Directory pins bind device/inode/owner/mode for the snapshot parent, private inputs, journal root, journal state and receipt directory.  Those directories are distinct; inputs, journal/state and receipts require mode `0700`, and private input/receipt custody belongs to the current process.  Snapshot-parent mode is exactly reviewed `0700` or `0755`.  Every component is opened without symlinks, and each held directory is rechecked against its original absolute path before use.  Fresh host scope bytes and their digest require independent review alongside the finite plan; no existing scope or owner value is inferred.

Before any file body read, the adapter checks its named snapshot bind and named journal source against the full pinned Engine inspect context.  The finite wrapper now passes the most recent checked stopped/replacement inspect into the corresponding proof phase without adding Engine calls; IDs, image/config/mount projection, name and running state remain exact.  The adapter does not independently authorize or query the daemon.  Daemon verification remains with the reviewed Engine transport and finite lifecycle.

The preflight phase verifies the exact local reservation record and creates the common snapshot-parent `.telemetry-hub-operation-lease.json` exclusively, then holds a nonblocking advisory lock on its verified inode.  The record binds owner session, old container, finite-plan hash and host-scope hash; durable private intent/confirmation receipts accompany it.  Different receipt roots cannot acquire separate ownership of the same snapshot parent through this adapter.  The common lease file remains after success or failure and is never automatically removed; another run requires explicit reconciliation and a separately reviewed cleanup decision.  The lock closes only after synchronous proof work returns.  This is cooperative ownership, not exclusion of unrelated writers that ignore the protocol.

Snapshot/input/state reads require bounded regular files, exact owner/mode `0600`, one hard link, no symlink following and stable device/inode/size/timestamps across the read and final directory entry.  Recovery creates four exclusive durable private backups: exact old snapshot, full old inspect, pinned create payload and reconstruction metadata.  Every backup is read back before stop eligibility.  The stopped transition records intent, stages one fixed private file with preserved custody and fsyncs it.  After all intervening reservation/snapshot/journal checks, it reopens the stage without following links and verifies exact bytes, original identity and complete original stat signature immediately before one descriptor-relative rename.  It then fsyncs the directory and verifies exact new bytes and unchanged stopped journal.  A landed rename followed by a deadline/fsync/readback failure is terminal and is never rolled back automatically; partial stage/backup/intent files are retained for reconciliation.  The final compare/rename race against noncooperating writers remains.

Journal sampling reads only bounded `journal.base.json` and `sentry.offset.json`, then stats `journal.jsonl` and optional `dead-letter.jsonl`; event bodies are never opened.  A second metadata sample rejects observed changes.  The required `files` proof retains device/inode/owner/mode/size/mtime/ctime/link-count signatures for all four files, plus raw-body hashes for the two state files; an absent dead-letter file is distinct from an empty file.  Exact physical fingerprints must survive stopped-transition and prestart comparisons, so same-size rewrites or inode replacement cannot pass as unchanged aggregate offsets.  After startup, physical changes may accompany valid journal progress, so the existing same-volume/nondecreasing end/offset and unchanged dead-letter-size rules remain; that phase does not require identical file fingerprints.  Base/nextBase must agree, pendingSize must be zero, offset must lie within the logical end, integers must remain within JavaScript's safe range, and the journal device must match the pinned root.  Concurrent activity can make a sample fail; there is no automatic retry or claim that local continuity proves receiver storage.

`DurableReceipts` creates at most 64 distinct `0600` receipt files exclusively, fsyncs each file and its directory, and verifies exact bounded bytes before acknowledging the canonical data hash.  Repeated names, failed writes/fsyncs or mismatched readback seal the sink; no partial file is deleted or reused.  The finite wrapper passes the active phase budget to this sink and closes proof/sink resources after all synchronous operations return.  Close failures prevent a successful result.  The host adapter's default `RefusingMountedReader` remains unconditional; a separately reviewed reader must establish the actual stopped/healthy container snapshot from the exact ID, independently of the host path.

Twenty-three host tests use actual temporary filesystem files and a fake Engine, including full durable flow, partial writes/fsync failure, directory substitution, symlinks/hardlinks, same-byte mutation during read, corrupt backup readback, changed reservations, competing snapshot writes, landed-rename ambiguity, compaction/offset rejection, metadata-only journal sampling, a shared lease across separate receipt roots and an old-inode descriptor that prevents startup.  Review regressions additionally tamper with the stage during intervening checks, rewrite/replace each stopped journal file at the same size, replace state inodes during sampling and reject prestart physical changes while allowing valid poststart progress.  They run under the host user's real fixture UID/GID.  Only a test subclass translates that ownership for the finite model's fixed UID/GID `10001` boundary; a separate test confirms the unmodified production boundary refuses the host user's ownership before stop.  These tests establish POSIX behavior on synthetic files, not successful production UID assignment, real mount readback or runtime activation.

## Remaining Acceptance Gaps

The production image/field set, current daemon/target identities, fixture-label/path substitution review, host-network boundary and concrete isolated executor remain pending.  The host adapter and receipt sink require independent source review, exact production scope/pins and authorized execution wiring; current evidence is synthetic.  Actual container snapshot readback and a finite mutation transport are still unavailable.  Stopped journal stability, production UID/custody, writable-layer recovery limits and cooperative one-writer ownership require fresh production evidence before any destructive boundary.  A reviewed reconstruction hash is not an automatic rollback capability.  Final sender, stored Sentry and Usage Monitor ACK/ledger acceptance remain separate from Engine representation and local journal continuity.  No rehearsal result or metadata-only health result closes those gaps.
