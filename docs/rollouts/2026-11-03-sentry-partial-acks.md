# Durable Sentry Partial ACK Holds

The Sentry hub previously treated every HTTP 2xx response as full acceptance.  The sender now reads at most 64 KiB of response bytes and validates the signal's OTLP rejection count, including safe integer strings.  Empty compatible responses and JSON full success continue to work; a zero rejection warning also succeeds.  A live empty-request probe returned HTTP 200 with `application/json` and `{}` for both logs and traces without emitting telemetry events.  Explicit incompatible content types, malformed or oversized success replies, and positive partial rejection counts stop Sentry delivery without retrying the ambiguous batch.  Free response messages, rejection bodies and headers are never persisted.

Before each POST, the journal durably publishes one private `state/sentry-request.json` intent containing the full scrubbed metadata batch, original event IDs and a stable digest.  File fsync, atomic exclusive publication and directory fsync precede the request.  A partial or ambiguous success updates that file with only a typed response class, HTTP status and any validated rejection count.  The rejection count does not identify which records failed, so the whole batch remains held while confirmed delivery and rejected counts stay separate.  Its independent metadata copy survives journal compaction; the older ID-only dead-letter record is insufficient for this purpose.

The Sentry channel holds while a prepared, held or invalid intent exists, including after restart.  It emits one count-only warning per sender instance and retains the journal offset.  A normal full success persists its sent receipts before clearing the intent.  Explicit HTTP failure and bounded same-process transport retries retain their existing contract.  A crash with an unresolved pre-POST intent conservatively requires reconciliation even if the request was never sent or a success receipt was already written.  This trades automatic recovery for preservation and avoids guessing which records may be retried; no automatic hold deletion or batch replay is introduced.  Preserve the intent file, payload and event identities before any manual reconciliation.  The other delivery destinations remain independent.

This fixes a confirmed ACK-validation weakness.  The historical Claude catch-up was independently verified in Sentry in full; partial response loss was not established as its cause.  Focused Node tests exercise real journal files, restart and compaction, file and directory fsync failures, strict ACK schemas, safe warnings, valid siblings around an HTTP 400 rejection, and a confirmed trace chunk followed by ambiguous logs.  The suite runs through the existing collector runtime CI gate.
